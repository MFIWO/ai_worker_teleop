AI Worker SH5 팔·손 통합 Teleop / VR·Loop 적용 안내
갱신: 2026-10-23 (KST)

============================================================
0. 브랜치 선택과 기본 조건
============================================================
저장소: https://github.com/MFIWO/ai_worker_teleop

robotis-applications: SH5 팔·손 통합 Teleop 중심, --loop off --input controllers
main: 같은 Teleop 기반 + 이번 VR·Loop 녹화/키보드 연동, --loop vr --input controllers
Loop까지 사용할 PC는 main을 받으면 팔·손 Teleop 코드도 함께 포함됩니다.
기존 main의 SG2 backport/Loop 참고 코드는 기록으로 보존됩니다.

현재 네트워크 예시:
  PC_IP=192.168.6.2
  ROBOT_IP=192.168.6.50
  SSH 별칭=ffw-SNPR48A1114.local
다른 PC/로봇에서는 실제 주소로 바꾸세요. PC_IP는 Quest가 접속할 PC 주소입니다.

PC 조건: Docker Engine + Docker Compose v2, robotis-applications 컨테이너.
로봇 조건: ai_worker 컨테이너, ROS Jazzy, Cyclo 소스/빌드 환경,
SH5 follower, 원본 ROBOTIS retargeting_teleop 및 SH5 손 모델.
이번 호환 코드는 Cyclo jazzy 651aa55와 기존 commissioning 소스 기준입니다.
다른 소스 버전은 빌드 검증에서 거절될 수 있습니다.
Loop 모드에는 로봇의 ffw_loop_streamer와 loop_sdk, PC의 Loop 앱도 필요합니다.
로봇의 기존 Loop 패키지는 이 저장소의 오래된 참고 패키지로 덮어쓰지 않습니다.
설치/소스 복사는 로봇을 움직이지 않습니다. --bringup 실행은 초기화 동작을 포함합니다.

4A. 팔·손 Teleop만 실행 — PC 터미널 두 개
============================================================
# 터미널 1: robot session (--bringup은 없는 router/follower를 시작)
bash ~/Downloads/external_repos/ai_worker_teleop_deploy/teleop.sh robot \
  --pc-ip 192.168.6.2 --robot-ip 192.168.6.50 --loop off --input controllers --bringup

# 터미널 2: PC Vuer
bash ~/Downloads/external_repos/ai_worker_teleop_deploy/teleop.sh pc \
  --pc-ip 192.168.6.2 --robot-ip 192.168.6.50 --loop off --input controllers

Quest 접속:
https://192.168.6.2:8012?ws=wss://192.168.6.2:8012
컨트롤러·몸 추적을 유지하고 A+X로 시작/재개, B+Y로 HOLD합니다.
각 손 trigger 누른 정도로 grasp 깊이 조절, grip으로 엄지·검지·중지 pinch.
Grip이 trigger보다 우선하며 pinch 중 약지·새끼는 열립니다.
기존 SG2 스틱 매핑을 재사용합니다. 양쪽 스틱 클릭으로 목/mobile 모드 전환, 오른쪽은 lift.
손 속도 제한은 물리 URDF 한계의 85%이며 HOLD는 토크를 끄지 않습니다.
Pinch/grasp는 모델 기반 초기값이며 실물 접촉/파지 검증은 아직 하지 않았습니다.
--loop off에서는 Loop 키보드 브리지를 실행하지 않으므로 C 키 조작을 사용하지 않습니다.
SH5 follower는 init_position:=false로 시작하여 기존 손/목/lift/steering 초기화 궤적을 생략합니다.
그 뒤 팔 7관절씩만 기존 xr_tele 준비 자세로 5초 동안 서서히 이동합니다. 손 준비 자세 궤적은 보내지 않습니다.
기존 follower가 실행 중이면 자동 준비 동작은 생략합니다. 필요하면 robot 명령에 --ready-pose를 추가합니다.
이미 실행 중인 옛 초기화 executor는 먼저 종료해야 합니다. 드라이버의 기존 손 전류 설정/토크는 별개입니다.
A+X/C 재개 때에는 이 5초 동작을 반복하지 않습니다.

============================================================
4B. 팔·손 + VR·Loop 녹화 (Quest 컨트롤러) — PC 터미널 두 개
============================================================
PC에서 Loop 앱을 먼저 엽니다. 물리 leader는 종료한 상태로 진행합니다.

# 터미널 1: robot session
bash ~/Downloads/external_repos/ai_worker_teleop_deploy/teleop.sh robot \
  --pc-ip 192.168.6.2 --robot-ip 192.168.6.50 --loop vr --input controllers --bringup

# 터미널 2: PC Vuer + Quest 컨트롤러
bash ~/Downloads/external_repos/ai_worker_teleop_deploy/teleop.sh pc \
  --pc-ip 192.168.6.2 --robot-ip 192.168.6.50 --loop vr --input controllers

PC를 먼저 실행해도 Zenoh 7447 포트를 최대 120초 기다립니다.
[WAIT ZENOH]가 나오면 다른 터미널에서 robot 명령을 실행합니다.
Loop Preview source: AI Worker VR / HX5-D20 (source key: robotis-vr-sh5)
robot type: ffw_sh5_vr / action space: joint_position / finger type: HX5-D20
업데이트 후 기존 Preview 설정을 다시 열어 HX5-D20 옵션과 새 채널을 선택합니다.
같은 VR 소스에 양손 20관절 관측/명령과 각 손 45개 fingertip 압력을 함께 기록합니다.
mobile odometry/cmd_vel, 카메라, teleop 상태 기록도 계속됩니다.
압력 입력: /left_hand/finger_pressures, /right_hand/finger_pressures
타입: robotis_interfaces/msg/HandPressures. 기존 follower의 pressure broadcaster를 구독합니다.
압력 채널: ffw_sh5_vr.observation.left_hand.tactile_pressure (right_hand도 동일)
순서: finger_l/r_sensor1~5, 센서마다 Present Pressure 1~9 (3x3 행 우선).
값은 원본 0~255이며 뉴턴 단위 힘이나 RH5DG2의 손바닥/방향/근접값이 아닙니다.
30Hz 기록 틱에서 최신 압력을 저장하며 수신 Hz, ROS 원본 시각, 수신 순번도 함께 기록합니다.
상위 토픽이 더 빠르면 모든 원본 프레임을 보존하지는 않습니다.
C/HOLD 중에도 압력 기록은 계속됩니다. 누락/형식 오류/0.5초 초과 지연은 0 대신 결측 처리합니다.
정상 수신 로그: [HX5-D20] left/right: valid 5x3x3 raw tactile received
구형 드라이버에 메시지/토픽이 없으면 경고와 결측 표시가 나오며 나머지 기록은 계속됩니다.
실제 로봇의 토픽/센서 수신은 연결 후 확인해야 합니다. 별도 손 bringup은 중복 실행하지 않습니다.
Loop의 기존 robot 채널로 표시/저장하며 전용 손 히트맵 UI를 추가하는 변경은 아닙니다.
조이스틱의 tact_trigger 버튼 이벤트는 손의 tactile 센서 데이터와 다른 기능입니다.
녹화 시작은 Loop에서 별도 실행합니다. C는 녹화 시작 키가 아닙니다.
카메라 없이 joint/tactile/status만 보내려면 robot 명령에 --loop-no-camera를 추가합니다.

컨트롤러 모드에서는 Loop 키보드 브리지를 실행하지 않습니다. 녹화/검토 키는 원래 Loop 기준입니다.
손 입력 4개는 teleop.controller_inputs에 HOLD 중에도 기록됩니다.

아래 키보드 조작은 두 명령 모두 --input hands로 바꾼 광학 손 모드에만 해당합니다.
Loop 창에 포커스가 있을 때:
  C: 팔·손 시작 / HOLD / 재개
  WASD: mobile 전후좌우
  O/P: 왼쪽/오른쪽 회전
  방향키: 목 tilt/pan
  U/I: lift 상승/하강
  Shift+A 또는 Loop 버튼: 녹화 시작 (검토 화면에서는 Loop의 기존 기능)
  V 짧게: 검토 화면에서 실패 저장
  V 길게: 검토 화면에서 폐기
Loop UI의 C/Hold C 표시는 그대로지만 VR 브리지가 이 키 기능을 V로 전달합니다.

U/I는 leader와 같은 실측 위치 ±10mm 목표를 100Hz로 갱신합니다.
이는 목표 offset이며 실제 이동 속도는 모터 응답과 물리 한계에 따릅니다.
C HOLD 중에도 같은 에피소드의 영상/토픽/데이터는 계속 기록하고 paused를 남깁니다.
학습용으로 제외할 때는 action_valid/paused를 기준으로 모든 스트림을 함께 처리합니다.

베이스 이동 시 팔은 HOLD됩니다. 이동 키를 놓아도 키보드는 계속 사용할 수 있습니다.
이동 후 키를 놓고 C를 한 번 누르면 현재 측정 자세로 재앵커하여 재개합니다.
C에서는 새 스냅샷/충돌 테스트/모델 재생성/컨트롤러 재시작을 하지 않습니다.
바퀴 6관절도 실시간 측정 모델에 포함하여 베이스 이동 후 프로필 교체를 없앴습니다.
정상 추적·피드백 상태에서 C→READY 약 0.1초를 목표로 설정했습니다.
별도 settle/활성화 대기=0, native ramp=0.03초, 양팔 출력 확인 후 추적을 시작합니다.
최초 세션 실행 때의 모델 준비는 한 번 필요합니다. 실제 모터/네트워크 지연까지 0.1초를 보장하는 것은 아닙니다.
[BASE REANCHORED] 로그가 나오며, 이동 키를 놓은 뒤 disarm 응답이 신선해야 재개합니다.
이 변경은 로봇 helper 설치와 별도 SH5 바이너리 --rebuild가 한 번 필요합니다.
기존 프로필 조회가 끊긴 경우에도 3초 후 재조회하여 HARDWARE_PROFILE_REQUIRED 고착을 방지합니다.
[LOOP FOCUS] inactive면 Loop 창을 클릭하고 키를 놓은 뒤 다시 누르세요.
[LOOP KEYS BLOCKED]에는 프로필/피드백/fault 등 차단 이유가 출력됩니다.

5. 종료 — bringup 노드가 남지 않게
============================================================
두 명령 중 어느 터미널에서든 Ctrl+C 또는 창 닫기를 하면 종료를 감지합니다.
명령 출력 중단 → 종료 감지 후 최소 3초 대기 → SH5 follower 정리 → 손가락 40개 토크 OFF.
PC/Vuer heartbeat가 끊기는 경우에는 감지(1.5초)와 ROS 종료/통신 확인 시간이 추가됩니다.
손을 펴는 자세 명령은 보내지 않고 각 모터 Torque Enable=0을 쓰고 다시 읽어 확인합니다.
성공: [HAND TORQUE OFF] Verified 40/40 finger motors
실패: [HAND TORQUE OFF FAILED] — 이때 실제 토크 해제는 확인되지 않은 상태입니다.
B+Y/C HOLD는 토크 OFF가 아니며 기존대로 빠르게 재개합니다.
터미널 종료 후에는 robot/pc 명령을 다시 실행하여 follower부터 시작합니다.

세션이 시작한 controller, retargeter, Loop streamer, SH5 follower와 자식을 정리합니다.
재사용한 SH5 follower도 손 토크 해제를 위해 함께 종료합니다. 외부 Zenoh router는 유지합니다.
SH5 launch 부모를 특정할 수 없는 기존 follower는 거절되므로 먼저 종료하고 --bringup으로 실행합니다.
호스트 터미널과 SSH/docker 사이의 stdin lease가 닫힘/연결 끊김을 감지합니다.
창을 닫은 경우 robot session의 exit.log에 정리 결과를 남깁니다:
  /workspace/ai_worker_xr_sessions/<id>/exit.log
직접 docker exec 명령 대신 위 teleop.sh 두 명령을 사용해야 호스트 lease가 적용됩니다.
포트를 다른 프로세스가 사용 중이면 중복 연결을 거절하고 토크 OFF 실패를 표시합니다.
컨테이너 강제 종료/전원 단절/정리 프로세스 자체의 강제 kill은 소프트웨어 종료 처리를 보장하지 않습니다.

# 로봇 컨테이너의 PID/실행 상태 확인 (호스트 PID와 혼동하지 않기):
ROBOT_IP=192.168.6.50
ssh "robotis@$ROBOT_IP" 'docker exec ai_worker ps -eo pid,args'

# 이전 launch를 정리할 때: 위 목록의 정확한 SH5 ros2 launch PID를 사용
# ssh "robotis@$ROBOT_IP" 'docker exec ai_worker kill -INT <컨테이너의_SH5_launch_PID>'

로봇 host에서 ros2가 없다는 것은 ROS가 컨테이너에 설치돼 있기 때문입니다.
# ROS 노드 목록:
ssh "robotis@$ROBOT_IP" 'docker exec -i ai_worker bash -s' <<'ROS_LIST'
source /opt/ros/jazzy/setup.bash
source /root/ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=30 RMW_IMPLEMENTATION=rmw_zenoh_cpp
ros2 node list
ROS_LIST

7. 손 빨간 점멸 / 발열 확인 사항 (2026-10-23)
============================================================
로봇 드라이버가 꺼진 상태에서 손 보드를 READ하여 양손 HardwareError=0x40,
